# UI でまだできない操作

エディタの UI を実際に操作して, ユーザーがやりたいのに UI からはできない操作を洗い出したもの (2026-10-31, main `5ec54fd`)。
ローカル (`npm run dev`) で UI からアカウントを作り, 新しいプロジェクト・モジュール・パーツを作って編集・コミット・実行・ブランチ作成までを
Playwright で操作して確かめた。直したらこの一覧から消し, 該当する docs に書く。

## 式・型の編集

| できないこと                                               | 今の動き                                                                                                                                                                                                                        | 関係するコード                                                                          |
| :--------------------------------------------------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | :-------------------------------------------------------------------------------------- |
| 関数の引数を後から足す・消す                               | 引数は新しいパーツの作成時 (`引数 (カンマ区切り)`) にしか決められない。型の行の `function` の選択肢は `x: number → number` の 1 引数の雛形に置き換えるだけで, 値の `fn` にも引数の追加・削除の操作が無い (名前の変更だけできる) | `src/tree_layout/selector_options.ts`, `src/tree_layout/rename_arguments.ts`            |
| レコード型のフィールドを足す・消す・名前を変える           | 型の選択肢の `record` は `{ key: string }` の雛形だけ。フィールド名はバッジ (`identifier`) で編集できず, フィールドの追加・削除の操作も無い                                                                                     | `src/tree_layout/ast_to_layout/collections.ts`                                          |
| 直和型のタグを足す・消す・名前を変える, タグに値を持たせる | `union` は `a \| b` の雛形だけ。タグのバッジを押すと `union` 全体の置換メニューになる                                                                                                                                           | 同上                                                                                    |
| レコードの値 (`record`) を作る                             | 式の選択肢に `record` のリテラルが無い (`core.expression.record` の Variant は出るが, それは式を表す値を作るもの)                                                                                                               | `src/tree_layout/selector_options.ts` (`expr:*` の一覧)                                 |
| レコードのフィールドを取り出す (`record_get`, `p.key`)     | レコード型の変数 `p` を選んでもフィールドの選択肢は出ない。式の選択肢にも `record_get` が無い                                                                                                                                   | `src/tree_layout/selection.ts`                                                          |
| 数を検索欄に打って数のリテラルにする                       | 検索欄に `21` と打つと「一致する候補がありません」。`number` を選んでから `0` のバッジを押して入力欄で書き換える必要がある。`number` を選んだ直後も入力欄にフォーカスしない                                                     | `src/tree_layout/ExpressionPopoverMenu.tsx`, `TreeLayoutRenderer.tsx` (`literalNumber`) |

レコードと直和型は, 型パーツを作って値を作る・中身を読むところまでを UI だけで書けないので, seed の JSON を書くしかない。

## コミットしていないパーツ

| できないこと                                           | 今の動き                                                                                                                                                                                                                                                                                                 |
| :----------------------------------------------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| コミットしていない新しいパーツを他のパーツから参照する | 置換メニューで探しても出ない。新しいパーツは `partIdHash: null` (`src/new_part.ts`) で, 選択肢はパーツ ID のあるパーツだけ (`selector_options.ts` の `ref:part:`)。パーツ ID はモジュール ID + パーツ名から決まる ([content-addressed.md](content-addressed.md)) のでコミット前でも求められるはず        |
| コミットしていない新しいパーツを実行パネルで実行する   | 「`module.name` を入力」ボタンが出ず (`RunPanel.tsx` の `openPart.partIdHash == null`), 置換メニューでも見つからない                                                                                                                                                                                     |
| 作業中の変更の一部だけをコミットする                   | コミットはプロジェクトの全部の変更が入る。未入力のある別のパーツがあるとコミットできないので, 上の 2 つと合わせると「`double` を作って, それを使う `quad` を作る」には `quad` を破棄して `double` だけ先にコミットし, それから `quad` を作り直す必要がある。新しいパーツ同士の相互再帰は UI では書けない |

## 名前の変更・移動・削除

| できないこと                                                                   | 今の動き                                                                                                                                                                                                                                                                                                      |
| :----------------------------------------------------------------------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 参照されているパーツの名前を変える                                             | パーツ名の入力欄で変えられるが, パーツ ID が名前から決まるので参照している他のパーツが壊れる (`part_not_found (part_definition_event_hash: "…")` の型エラーでコミットできない)。参照側は自動で直らず, 参照側のページでは古い名前のまま表示されエラーも出ない。名前を変えても URL は `/part/{古い名前}` のまま |
| パーツを別のモジュールへ移す                                                   | パーツ定義の `module` の行は表示だけ                                                                                                                                                                                                                                                                          |
| モジュールの名前の変更・説明の編集・削除                                       | モジュールのページは公開範囲の切り替えと「+ 新しいパーツ」だけ。UI で作ったモジュールは説明が空のまま                                                                                                                                                                                                         |
| プロジェクトの名前の変更・説明の編集・削除, モジュールを他のプロジェクトへ移す | プロジェクトのページはブランチの作成・取り込みとコミット履歴だけ ([project.md](project.md)「今後」)                                                                                                                                                                                                           |
| ブランチの削除・名前の変更                                                     | 作るだけ ([branch.md](branch.md)「今後」)                                                                                                                                                                                                                                                                     |
| main の変更を自分のブランチに取り込む                                          | 取り込みは「ブランチを main に」の向きだけ ([branch.md](branch.md)「今後」)                                                                                                                                                                                                                                   |
| アカウント名・アイコンの変更                                                   | アカウントのダイアログ・ページは表示, 秘密鍵のコピー, ログアウトだけ                                                                                                                                                                                                                                          |

## 履歴と差分

| できないこと                                 | 今の動き                                                                                                                                         |
| :------------------------------------------- | :----------------------------------------------------------------------------------------------------------------------------------------------- |
| コミットする前に変更の中身 (差分) を見る     | 変更のページはパーツ名・「新規」の印・説明だけ。式や型がどう変わったかは出ない. 名前を変えたパーツも新しい名前だけで, 元の名前は出ない           |
| コミットで何が変わったか (親との差分) を見る | コミットの詳細は全パーツの一覧とハッシュだけ                                                                                                     |
| 古いコミットのパーツを見る・その版に戻す     | コミットの詳細のパーツのリンクは `/part/{名前}` で, 表示しているブランチの最新の版を開く。エクスプローラーも各ブランチの最新のコミットだけを出す |

## 調べ方

- `npm run dev` には Node 26 が要る (`src/cbor.ts` が `Uint8Array.prototype.toBase64` を使う)。Node 22 だと `build:seeds` が `bytes.toBase64 is not a function` で落ちる
- Playwright の `launchPersistentContext` でプロファイルを残すと, UI で作ったアカウント (`definy.account.v1`) と作業中の変更が次の実行にも残るので,
  1 操作ずつ別のスクリプトにして `ariaSnapshot()` とスクリーンショットで確かめられる
- 置換メニューの候補は `.dropdown-option`, 検索欄は `.dropdown-search-input`, 式のバッジは `.tree-badge`。
  パーツ詳細の行は `[role=treeitem]` で, 先頭の文字 (`type` / `value`) で選べる
