# モジュールのブランチ

definy には GitHub のフォークは無く, ブランチだけで編集を分ける (2026-10-24 の決定, issue #765)。

- ブランチはモジュールごとにある。モジュールの最初のコミットは `main` ブランチに入り, そのアカウントが `main` の作成者になる
  (core など seed のモジュールはシステムアカウント)。
- 誰でも新しいブランチを作れる。ブランチにコミットできるのはそのブランチを作ったアカウントだけ。
- 他のアカウントのモジュールを変えたいときは, そのモジュールに自分のブランチを作ってコミットする。

## ID

モジュール ID はモジュール名だけで決まる (`deriveModuleIdBytes(moduleName)`, `src/cbor.ts` / `worker/cbor.ts`)。
パーツ ID は `H(モジュール ID, ":part:", パーツ名)` なので, 同じモジュールのどのブランチでも同じパーツは同じ ID になる。
以前はモジュール ID がアカウントとモジュール名で決まり, 同じ名前のモジュールでもアカウントごとに別のモジュールだった。

## コミット

`core.module-commit` に `branch: string` がある ([event.md](event.md))。規則は definy 製の `core.check-event-branch`
(`core.check-event` から呼ぶ) が決める:

| 状況                                          | 受け付けるコミット                                         | 理由 (`core.event-rejection`)                         |
| :-------------------------------------------- | :--------------------------------------------------------- | :---------------------------------------------------- |
| ブランチ名が空                                | 受け付けない                                               | `empty_branch_name`                                   |
| モジュールにまだコミットが無い                | `main` に親無し                                            | `first_branch_must_be_main`, `parent_commit_mismatch` |
| ブランチがある                                | ブランチの作成者だけが, ブランチの最新のコミットを親にする | `not_branch_creator`, `parent_commit_mismatch`        |
| ブランチが無い (モジュールにはコミットがある) | 誰でも, 同じモジュールのどれかのコミットを親にする         | `parent_commit_mismatch`                              |

- ブランチの作成者は, そのブランチの最初の (時刻が最小の) コミットのアカウント。
- ブランチの最新は時刻が最大のコミット。同じ秒のコミットは先のものが最新のままになる (`pickLatestCommitPerModule` と同じ)。
- 規則が使う状態 (`core.event-check-state`) はサーバーがストアから集める (`branchStateOf`, `worker/type_check.ts`):
  `branch_latest_commit_hash`, `is_branch_creator`, `module_has_commits`, `parent_in_module`。

## サーバーの型検査

コミットを型検査するとき, コミットするモジュール以外のパーツは各モジュールの `main` の最新のコミットのものを使う
(`loadLatestMainCommits`)。ブランチのパーツは他のモジュールから見えない。

## UI

- ブランチの一覧はサーバーの `GetModuleBranches` から受け取る (ブラウザは全イベントを読まない. [ui.md](ui.md)「読み込むイベント」)。
  ブランチの集計はサーバーの `summarizeBranches` (`src/branches.ts`)
- 表示するブランチはモジュールごとに選ぶ (モジュールのページの「ブランチ」. 既定は `main`, localStorage `definy.selected_branches.v1`)。
  モジュール・パーツの一覧, パーツの詳細, 型環境 (`committedParts`) は各モジュールの表示しているブランチのものになる
  (`useEvents`)。
- コミット履歴は表示しているブランチの最新のコミットから親をたどる (読んでいないコミットは 1 件ずつ読む, 50 件まで)。ブランチを作る前の `main` のコミットも入る。
- 作業中の変更は表示しているブランチに重ねる。コミット先は `commitTarget` (`src/branches.ts`) が決める:
  - モジュールにコミットが無い → `main` に親無し (新しいモジュール)
  - 表示しているブランチを自分が作った → そのブランチに, その最新のコミットを親に
  - 他のアカウントのブランチ → そこから新しいブランチを作る。名前は変更のページで決める (既定はアカウント名. 使われていれば `-2`, `-3`, ...)。
    コミットすると新しいブランチを表示する
- 注意: UI の型検査は表示しているブランチで型環境を作るが, サーバーは他のモジュールを `main` で検査する。
  他のモジュールのブランチを表示したままコミットすると, UI では通ってもサーバーで型エラーになることがある。

## 取り込み

他のブランチの変更を main に入れる (GitHub のプルリクエストのマージにあたる)。

- `core.module-commit` の `merged_commit_hash: option<string>` に取り込んだコミットを持つ。親 (`parent_commit_hash`) は今までどおり
  コミット先のブランチの最新のコミット。規則は `core.check-event-merge`: 取り込むのは同じモジュールのコミット
  (`merged_commit_not_in_module`. 状態 `merged_in_module` はサーバーが集める)。取り込むコミットを選べるのはコミット先のブランチの作成者だけ
  (ブランチの規則と同じ)
- UI: main を作ったアカウントがモジュールのページで他のブランチを表示すると「… を main に取り込む」が出る
  (`src/components/MergeBranchPanel.tsx`)。押すと
  1. 共通の祖先 (取り込みの基準) を探す (`findMergeBase`, `src/merge.ts`)。親と取り込んだコミットをたどり, 読んでいないコミットは `GetEvent` で読む
  2. パーツ名ごとの 3 方向マージ (`mergeParts`): 片方だけが変えたパーツはその変更を使う。両方が違うように変えたパーツ (衝突) は
     取り込む側を使い, モジュールのページに知らせる。無いパーツは削除として扱う
  3. main のパーツとの差を作業中の変更にし (`mergeToWorkingChanges`. 無くなったパーツは `deleted`), 取り込むコミットを
     `WorkingChanges.merges` に入れ, main を表示する。変更のページで確かめ (型検査も), コミットすると `merged_commit_hash` が入る
- 取り込む前にそのモジュールの作業中の変更があれば取り込まない (先にコミットか破棄)。取り込みをやめると作業中の変更も捨てる
- 取り込むものが無ければ (main にもう入っている) 何もしない
- モジュールのページのコミット履歴は, 取り込みのコミットに取り込んだコミットへのリンクを出す (履歴は親だけをたどる)

## seed の書き戻し

`export:seeds` はシステムアカウントの `main` のコミットだけを書き出す (`src/seed_export.ts`)。
他のアカウントのブランチは seed に入らない。
