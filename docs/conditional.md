# 条件分岐 (Bool に対する match)

definy には if 式がありません (#653)。条件分岐は Bool に対する `match`
式で書きます。

```text
match (less_than x 10) {
  true => "small",
  false => "large",
}
```

式 (`core.expression` の `match`) のアームのパターンに Bool のリテラル `{"#boolean": true}` / `{"#boolean": false}`
を使います。どの値にも一致するアームはパターン `{"#any": null}` のアームです (default の欄はありません)。
パターンの詳細は [match-pattern.md](match-pattern.md)。

式の種類を 1 つ減らすと、評価器・型検査・Wasm コンパイラ・フォーマッター・最適化器・UI
（いずれも自己記述版を含む）の分岐が減り、セルフホストの実装量が減ります。

## 各層での扱い

| 層                                                  | 扱い                                                                                                |
| --------------------------------------------------- | --------------------------------------------------------------------------------------------------- |
| 自己記述評価器 `core.eval-value`                    | `core.eval-pattern` が Bool のリテラルのパターンと対象の値を比べる                                  |
| 自己記述型検査 `core.type-check`                    | 対象の型が `boolean` なら `[{ tag: "true" }, { tag: "false" }]` という union として網羅性を検査する |
| 自己記述コンパイラ `core.compile-expr-instructions` | Bool の match を `if ... else ... end` 命令列に変換する (アーム本体は `core.match-arm-body` で取得) |
| 自己記述最適化器 `core.optimize-expression`         | 対象がリテラル `boolean` なら選ばれるアームの本体に畳み込む                                         |

UI の型エラー表示とサーバーの検査は自己記述型検査を使うので, 上の表のとおりに扱われる。

## 文字列に対する match

文字列の値にも `match` できます。アームのパターンに文字列リテラル (`{"#string": "plus"}`) を書き, 一致するアームの本体を評価します。
`_` (`{"#any": null}`) とは別のパターンなので, 文字列 `"_"` にも一致させられます。数値の値も同じように数値のリテラルで match できます。
文字列は取りうる値が無数にあるので, `_` のアームが必須です (無いと型エラー)。

```text
match name {
  "plus" => ...,
  "minus" => ...,
  _ => ...,
}
```

`match equal(name, "plus") { true => ..., false => match equal(name, "minus") { ... } }` のような入れ子を平らに書けます。

| 層                                        | 扱い                                                                                                |
| ----------------------------------------- | --------------------------------------------------------------------------------------------------- |
| 自己記述評価器 `core.eval-value`          | `core.eval-pattern` が文字列のリテラルのパターンと対象の文字列を比べる                              |
| 自己記述型検査 `core.type-check`          | 対象の型が `string` なら `[{ tag: "_" }]` という union として網羅性を検査する (`_` が必須)          |
| 自己記述コンパイラ `core.compile-pattern` | 対象の文字列の箱とリテラルの文字列をランタイム関数 4 (文字列の比較) で比べる                        |
| UI (`src/tree_layout/match_pattern.ts`)   | 文字列の match のアームのパターンを選ぶとき, 打った文字列をそのままリテラルにする選択肢を先頭に出す |
